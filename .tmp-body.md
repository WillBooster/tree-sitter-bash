## Why

This repository kept its own copy of the draft-first release logic (`script/release.mjs`, `script/releasePlugin.mjs`, `test/unit/release.test.ts`), as did the runtime and the other grammar repositories, so every fix had to be copied into each of them (WillBooster/tree-sitter#25). That logic now lives in `@willbooster/wb` 22.13.0 as the semantic-release plugin `@willbooster/wb/release-plugin` plus a pending-release step in `wb release`, already used by WillBooster/tree-sitter (WillBooster/tree-sitter#28).

## Requirements

- required: no repository contains a copy of the shared release logic or its tests (`script/release.mjs`, `script/releasePlugin.mjs`, `test/unit/release.test.ts`, `script/publish-crate`).
- required: `package.json` runs `"release": "wb release"` with `@willbooster/wb` >= 22.13.0 and without `@semantic-release/exec`; `semantic-release` and `conventional-changelog-conventionalcommits` stay.
- required: `.releaserc.json` keeps `branches: ["main"]` and the default `tagFormat`, and its plugins are the `conventionalcommits` commit analyzer, the release notes generator, and `["@willbooster/wb/release-plugin", { "pkgRoot": "." }]`, without `crate` because tree-sitter-bash publishes npm only.
- required: `script/build-release` and `script/set-grammar-version` stay.
- required: `.github/workflows/release.yml` keeps `workflow_dispatch`, `actions: write`, and the `concurrency` group, and its comments name `wb release` instead of deleted files.
- required: verified by a dry run on the pushed branch, and by one real release after merging: npm `latest` with provenance and the squash commit as `gitHead`, a published GitHub Release with its tag, and no leftover drafts or `release-pending/` branches.
- chosen: the PR is typed `fix:` so that merging it performs the real release this migration must verify.

## Customer Summary

Releases work as before; the release logic comes from the pinned `@willbooster/wb` instead of scripts in this repository.

## Technical Summary

1. `package.json`: `"release": "wb release"`, `@willbooster/wb` 22.13.0, and no `@semantic-release/exec`.
2. `.releaserc.json`: the `@semantic-release/exec` step and `./script/releasePlugin.mjs` are replaced by `["@willbooster/wb/release-plugin", { "pkgRoot": "." }]`, which runs `script/build-release <version>` itself before creating the draft and publishes npm and the GitHub Release. `script/set-grammar-version` still writes the version into `package.json`, `tree-sitter.json`, and `src/parser.c`.
3. Deleted `script/release.mjs`, `script/releasePlugin.mjs`, and `test/unit/release.test.ts` (the tests now live with `wb`). `.github/workflows/release.yml` comments now name `wb release`.

The Robustness workflow still reads the runtime version to fuzz with from `devDependencies["@willbooster/web-tree-sitter"]` in `package.json` (1.0.7), which this PR does not touch.

- The real release happens when this PR is merged, and is verified then.
